# ADR-0008: 클라이언트 라우팅·클라이언트 실행 도구

## 맥락

- Lemmy가 `/v1/realtime`으로 연결하면 검색·유튜브·날씨·뉴스 도구 사용 불가
- 도구 실행·화면 결과·권한은 Lemmy 소유(ADR-0003), real-PA는 Lemmy import 없는 독립 API(REQ-API-001 A09)
- Qwen3-8B(llama.cpp) 도구 호출 확인: 명시 요청은 호출, `밖에 나가도 될까?` 같은 간접 요청은 미호출
- 같은 간접 요청도 해당 도구 1개·`tool_choice=required`면 호출. 지역 미지정 시 `서울` 임의 생성 관찰

## 검토한 대안

| 대안 | 장점 | 비용·위험 |
| --- | --- | --- |
| 전체 도구를 매 턴 LLM에 노출 | 구현 단순 | 간접 요청 누락·프롬프트 증가·오선택 |
| 라우터 결과만으로 실행·템플릿 응답 | 모델 의존 없음 | 인자 추출·복합 요청·자연스러운 답변 한계 |
| 클라이언트 라우팅 + LLM 도구 호출 + 클라이언트 실행 | 턴별 도구 축소·간접 요청 강제 호출·업무 소유권 유지 | 턴마다 왕복 대기·프로토콜 추가 |

## 결정

- start에서 클라이언트가 도구 정의 목록 등록, real-PA는 실행 코드 없이 정의만 보관
- 발화 확정 후 real-PA가 `route_request` 전송, 클라이언트의 `route`로 이번 턴 도구 부분집합·`tool_choice` 결정
- LLM 도구 호출은 `tool_call`로 클라이언트에 위임, `tool_result` 수신 후 응답 계속
- route·tool 응답 시한 초과 시 도구 없이 진행 또는 실패 결과 전달, 무한 대기 금지
- 라우터 종류(키워드·Laya 등)와 인자 검증·기본값은 클라이언트 책임

## 결과

### 긍정적 결과

- 업무 실행·권한·UI는 Lemmy 유지, real-PA는 모델·세션·취소만 담당
- 라우터 교체가 프로토콜 변경 없이 가능

### 부정적 결과와 비용

- route 대기만큼 첫 응답 지연 증가, 도구 사용 턴은 실행 시간 추가
- 클라이언트가 도구 결과를 위조할 수 있으므로 결과는 클라이언트 신뢰 범위로만 사용

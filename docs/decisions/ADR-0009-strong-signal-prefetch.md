# ADR-0009: 강한 신호 조회 도구의 결정적 사전 실행과 fail-closed

[ADR-0008](ADR-0008-client-routed-tools.md)을 보완한다. ADR-0008의 클라이언트 라우팅·클라이언트 실행 구조와
"라우터 결과만으로 범용 인자 추출" 대안의 기각은 유지한다.

## 맥락

- ADR-0008 이후 강한 신호 1개는 `tool_choice=required`로 강제했다.
- 실제 음성 측정과 텍스트 다중 턴 재현에서, 도구 기록이 있는 세션의 llama.cpp `required` 라운드가 호출 앞에 긴 텍스트를 쓰다
  96 token 상한에 잘려 호출 없이 끝났다(검색 → 간접 날씨 → 우산, 2세션 중 1세션의 2턴).
- 실패 후 일반 답변으로 넘어가며 날씨를 조회하지 않고 "비가 올 가능성"을 생성했다. 라우터가 외부 정보가 필요하다고
  확정한 턴에서 모델 지식 답변 경로가 남아 있는 것이 핵심 문제다.
- 강제 라운드는 도구 턴마다 약 628ms(p50, 실제 음성)를 쓴다.

## 결정

- 강한 신호가 정확히 1개이고 그 도구에 결정적 인자 해석기가 있으며 해석이 확실할 때만, 클라이언트가 도구를 먼저 실행한다.
  real-PA는 `route.prefetched`의 결과를 이번 턴 도구 메시지로 넣고 도구 없이 답변만 생성한다.
- 해석기가 확신하지 못하면 임의로 채우지 않고 `auto`(모델이 인자를 채움)로 내려간다. 강한 신호에도 `required`는 쓰지 않는다.
- 사전 실행이 실패하면 `route.reply`의 고정 안내문을 LLM 없이 말한다(fail-closed). 외부 정보가 필요하다고 확정된 턴에서
  모델 지식으로 대신 답하는 경로를 두지 않는다.
- 범용 인자 추출은 여전히 기각한다. 해석기는 도구별 좁은 규칙이다(Lemmy `resolve_arguments`).

## 결과

### 긍정적 결과

- 확정 턴에서 호출 누락과 조회 없는 날씨 생성 경로 제거, 강제 LLM 라운드 제거로 도구 턴 지연 감소.

### 부정적 결과와 비용

- 해석기 규칙 범위 밖 표현(주말·요일 날짜, 목록에 없는 지명, 요청 대상 없는 "유튜브 틀어줘")은 모델 경로로 남는다.
- `auto` 경로의 실패는 여전히 모델 판단에 맡긴다(결과 오류는 성공 표현 금지 지침).

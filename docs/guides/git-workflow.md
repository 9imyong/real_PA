# Git 작업 흐름

## 브랜치

- 기본 브랜치는 항상 배포 가능한 상태를 유지합니다.
- 작업 브랜치는 짧게 유지하고 목적을 나타내는 이름을 사용합니다.
- 오래 지속되는 브랜치보다 작은 변경 요청을 선호합니다.

## 변경 요청

1. 변경 목적과 사용자 영향을 설명합니다.
2. 관련 요구사항, ADR, 작업 문서를 연결합니다.
3. 코드와 영향을 받는 문서를 함께 갱신합니다.
4. 검증 결과와 되돌리기 방법을 기록합니다.
5. 검토 의견을 해결한 뒤 병합합니다.

커밋 형식은 저장소 루트의 `COMMIT_RULES.md`를 따릅니다.

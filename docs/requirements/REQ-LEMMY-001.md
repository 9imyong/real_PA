# 요구사항: Lemmy 연동

## 목적과 문제

로컬 양방향 대화에서 Lemmy의 기능·기억·사용자 정책 재사용.
기존 기능의 별도 복제 및 인증·권한 우회 방지.

## 이해관계자

- 사용자: 본인의 메모·알림에 접근하고 한국어로 기능 실행
- Lemmy 유지보수자: 기존 데이터·도구·화면 계약 보존

## 인수 조건

```text
주어진 조건: 모델 확보 완료, 외부 네트워크 차단, Lemmy에 인증된 사용자와 알림 저장소 존재
실행할 때: “레미야, 내일 알림 보여줘” → 답변 중 “첫 알림 10분 전에 하나 더 알려줘”
기대 결과: 기존 음성 중단, 올바른 대상·시간 해석, 정책 통과 후 새 알림 1건 등록
추가 조건: 같은 요청 식별자로 재시도해도 등록 총수 1건 유지
```

- 모호한 대상·날짜·시간은 질문으로 확정한 후 등록
- 모델이 전달한 타 사용자 식별자는 실행 문맥 변경에 사용 금지
- 늦은 도구 결과는 원래 요청 상태에 기록, 현재 턴의 출력에는 자동 혼입 금지
- 완료된 등록을 음성 끼어들기만으로 취소 처리하지 않음

## 범위

### 포함

- provider-neutral 도구 정의·처리기 재사용 가능성 점검
- 권한 문맥·도구 식별자·실행 상태·중복 방지·UI 어댑터
- 기능 플래그를 통한 기존 경로와 신규 경로의 명시적 선택

### 제외

- 첫 버전의 실제 로봇 이동과 외부 통화
- 메모 삭제 등 첫 버전에서 허용하지 않은 도구
- 날씨·뉴스·검색의 인터넷 없는 최신 정보 제공
- Lemmy 전체 코드 복사와 데이터베이스 직접 쓰기

## 품질과 제약

- 권한 없는 요청의 실행 건수 0건, 사용자 간 데이터 혼입 0건
- 등록 중복 방지는 메모리 캐시만으로 완료 주장 금지, 저장소 기반 키·결과 기록 필요
- 전역 exactly-once 주장 금지, 정의된 키·보존 기간·트랜잭션 범위 내 보장만 보고
- UI와 공개 전송 계약 변경 시 전환·하위 호환성 검증 필수
- 기술 어댑터와 공개 계약 세부안은 T005 점검 후 확정
